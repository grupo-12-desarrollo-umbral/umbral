# Proxy performs optimistic cookie-only checks, no backend calls

`proxy.ts` decrypts the session cookie and redirects unauthenticated or deactivated users. It never calls the api-gateway or `identity-access-service`. The authoritative access check (`GET /api/permissions/authenticated-platform-access`) is the responsibility of backend guards, not the frontend proxy. Proxy runs on every prefetched route in Next.js 16; putting a backend call there would add a round-trip to every navigation and every `<Link>` prefetch, which is unacceptable for a dense operational UI. The cookie is tamper-proof (signed with `SESSION_SECRET`) so the optimistic check is not a security gap — it is a UX gate that keeps unauthenticated users out of the React tree. Real authorization lives in the backend.
