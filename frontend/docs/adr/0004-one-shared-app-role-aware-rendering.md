# One shared Next.js app with role-aware rendering, no separate admin/operator apps

Operators and Admins share a single Next.js app, a single session model, a single design system, and a single navigation shell. Within `/dashboard`, the two roles render structurally different layouts: the operator view is a session-centric surface (live leaderboard, clue control, submission queue, session controls), while the admin view is an oversight surface (cross-session metrics, operator assignments, configuration shortcuts). The `role` from the session selects which layout branch to render. There are no separate `/admin` and `/operator` route trees, no separate deployments, and no separate builds. The layouts differ in content and structure, but the infrastructure that surrounds them — authentication, proxy guards, session handling, the design system, the navigation sidebar — is identical and would have to be duplicated across two apps for no gain. If a future role requires a fundamentally different deployment target or security boundary (e.g., a participant-facing mobile experience), that warrants a separate app at that point.
